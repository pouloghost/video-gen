# Rewrite Principles
## Core Principles & Model Limitations
1. **Model Is a Renderer, Not an Editor:** The model *re-draws* an image based on your prompt. It **cannot** understand "editing" verbs (add, zoom, pan, change, make taller). You MUST describe the **absolute final state** using photographic and compositional terms.
2. **Model Is Bad at Layout:** The model struggles with complex layouts, multiple characters, and specific proportions. **You MUST use the Iterative Strategy to manage this.**
3. **Interpretation Priority:** For I2I model (DiT) image are stronger input than prompt, only use reference image when the character/setting occupies at least 1/8 of the frame. 
4. **I2I Model Sympathy:** Draft the image prompt using syntax and keywords common in text-to-image model training datasets (e.g., tags, specific descriptors), combined with professional photography terminology.

## Master Checklist (For ALL Prompt Types)
Your prompts must be a cohesive paragraph answering:
1.  **Shot & Composition:** Shot Type (Close-up, Medium, etc.), Angle (Low, High, etc.), Composition (Rule of thirds, centered, etc.). **Specify the exact position of all subjects according to the composition type, e.g. "rule of third ... a man in blue suit in foreground left, takes bottom half vertically".**.
2.  **Subject & Action:** Who/What (e.g., "An Eighth Route Army soldier"). What are they doing? (e.g., "standing solemnly at attention").
3.  **Features & Props:** Key features, clothing, props (e.g., "pale blue shirt").
4.  **Lighting & Atmosphere:** Lighting (Dramatic chiaroscuro, soft light), Mood (Solemn, Tense), Color (Warm, Cool).
5.  **Style & Medium:** Genre (cultural portraiture), Style (cinematic, hyperrealistic), Medium (Digital painting).
6.  **Lens & Focus:** DoF (Shallow, Deep), Bokeh, Lens (Telephoto, Wide-angle).

## Guidelines for Specific Prompt Types
### For `Text` Prompts:
Use the ENTIRE Master Checklist. Be descriptive, specific, simple sentences.
If a reference/setting image is present, but not useful for the scene, you MUST keep scene-setting visual consistency with your prompt.
If you can concisely describe the features and subject (not character) in referenced image, use `Text` rather than `Ref`.
Add "ratio 16:9" to the end of every prompt.
### For `Ref` Prompts:
Use Shot & Composition, Subject & Action, Features & Props, Lighting & Atmosphere, Lens & Focus in Master Checklist. Be descriptive, specific, simple sentences.
The reference image is normally not a start point of modification, start the prompt by tell I2I model this is reference (take styling and mood) not modification(change something in the base image). e.g. "Take the village style and architecture from image 1 as reference not starting point of modification.".
Try make the image shot & composition significantly different from the reference image, avoiding I2I model influenced too much by the reference image, ignore the prompt.
Add "ratio 16:9" to the end of every prompt.
### For `Modify` Prompts (The "Re-Renderer")
**Core Principle: Describe the FINAL STATE, not the PROCESS of change.**
Do not motion visual style unless changed.
#### 1. Banned "Process" Words
You **MUST NOT** use verbs or concepts related to video editing, animation, or gradual change.
**BANNED:** zoom in, push in, pan left, tilt up, add, change, remove, make taller, make smaller, slightly, a little, continue the..., etc.
#### 2. Required "State" Words
You **MUST** translate "movement" or "changes" into absolute, static, photographic terms. 
#### 3. Comparative "State"
If you are doing subtle changes or ambiguous descriptions which on it's own may cause confusion. Describe the base image first, emphasize the differences. e.g. The car runs fast (Image 1 is **relatively** fast) on the track.
#### Double-Check Validation: You MUST double-check every modify_prompt before outputting. If a modify_prompt contains any comparative or process-based words (e.g., 'closer', 'tighter', 'more', 'less', 'zoom in', 'pan left', 'add', 'change'), the output is invalid. You must rewrite it to describe the absolute static composition."
For example:
* INSTEAD OF Process (Camera Movement): "Zoom in on the man's eyes.". **USE State (New Composition):** "An **extreme close-up** on the man's eyes (from image 1)."
* INSTEAD OF Process (Add Subject): "Add smoke to the village.". USE State (New Props): "The village (from image 1) is **shrouded in thick smoke**."
* INSTEAD OF Process (Feature Change):** "Change the man's shirt to red." USE State (Final View): "The man (from image 1) **wears a vibrant red shirt**."
#### 3. Iterative Modify (Adding Subjects)
When using `Modify` to add subjects to a base image:
* **Be Precise:** Use absolute positional language. Your text *is* the mask.
    **Good:** "A two-shot composition. The background is the empty room from image 1. In the **right foreground**, the character from image 2 stands, facing left. In the **left middle ground**, the character from image 3 sits at the table."
* **One Subject Per Step:** This is the default, reliable path. Add one complex character or interacting element at a time.
* **2+ Subjects Per Step (Risky):** Only attempt this if the subjects are **generic** (no refs), **not interacting**, **spatially distant**, and have **simple poses**.
### Additional Requirements For `Base Frame` Scenario:
If this is the Base Frame for an Iterative Strategy:
* The `prompt` MUST describe the empty scene/background.
* You MUST fill the `final_scene` field with a detailed description of the *completed* scene. This is mandatory.

## Asset & Image Referencing
* **Mandatory:** If a Panel mentions character/setting IDs, you MUST include those filenames (e.g., `character_1.png`) in the `images` array for `Ref` or `Modify` prompts.
* **Filename Convension:** characters (character_[id]), settings (setting_[id]), keyframes from previous panels (scene_[panel_id]_[index]), iterative image from last iteration (iterate-[panel_id]-[index]-[iterate_time - 1], e.g. iterate-2-1-2), background is iterate_time 1.
* **Indexing:** The model recognizes images by their index.
    * In your prompt, `image 1` *always* refers to the **first** file in your `images` array.
    * `image 2` refers to the second, and so on.
    * For `Modify` prompts, the base image (e.g., `iterate-2-1-1` or `scene_1_1.png`) **MUST** be the *first* item in the `images` array, making it `image 1`.

## Forbidden & Replacements
- "3x3 grid composition", high risk generates grid border lines, use rule of third, then describe subject position instead.
- "realistic film", hight risk generates a realistic cartoon, just use "film".

# Common Errors
- Illegal modify_prompt. If a modify_prompt contains any comparative or process-based words (e.g., 'closer', 'tighter', 'more', 'less', 'zoom in', 'pan left', 'add', 'change', etc), the output is invalid. You must rewrite it to describe the absolute static composition.
- Wrong Reference. For I2I model, image input are way stronger than text. If an reference image only takes small portion of frame, remove it and change the prompt.
- Unnecessary styling. For Ref or Modify, base style is always taken from the base image, DO NOT state base style in prompt.
- Ambiguous items. For consective frames, key items must be emphasized in each frame. e.g. "a golden earing", never say "an earing".
- Dangerous Ref. For Ref, must emphasize ignoring composition and content (not detail) from referenced image.
- Explicit Screen Space Statement. The screen space for EVERY major element must be explicitly defined.
- Modify the Right Image. The filenames in image array must be in right format and correct image.
